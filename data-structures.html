Data Structures & Memory Layout

How data is physically and logically arranged in RAM. Analyze pointer indirection, cache locality, amortized dynamic growth, and tree balancing invariants.

1. Arrays vs. Linked Lists: Memory Topology

The two fundamental ways to store sequential elements in computer memory differ drastically in hardware CPU cache efficiency and time complexity:

Contiguous Memory

Arrays & Dynamic Vectors

Elements are laid out next to each other in physical RAM addresses. Accessing arr[i] requires simple pointer arithmetic: base_address + (i * sizeof(element)).

  • Random Access: O(1) constant time.
  • CPU Cache Locality: Extremely high spatial locality; adjacent items are prefetched into L1/L2 cache lines automatically.
  • Insertion / Deletion: O(n) due to shifting elements.
  • Amortized Expansion: Dynamic arrays (C++ vector, Java ArrayList) double capacity when full, achieving amortized O(1) append.
Pointer Chaining

Singly & Doubly Linked Lists

Nodes live anywhere on the Heap, connected via forward (next) and backward (prev) pointers.

  • Random Access: O(n) (must traverse sequentially from head).
  • Cache Performance: Poor due to scattered heap memory allocations causing frequent CPU cache misses.
  • Head Insert / Delete: O(1) without shifting.
  • Memory Overhead: Requires extra 8 bytes per 64-bit pointer per node.

3. Hash Tables & Collision Resolution

A Hash Table maps arbitrary keys to bucket indices using a hash function hash(key) % capacity, achieving average-case O(1) lookup, insertion, and deletion.

Separate Chaining

Each bucket points to a linked list or red-black tree (e.g. Java 8+ HashMap converts to a balanced tree when bucket chain length exceeds 8).

Bucket Node Structure
struct Node {
  string key;
  int val;
  Node* next;
};

Open Addressing (Probing)

All entries reside directly within the array. On collision, probe alternative slots:

  • Linear Probing: h(k, i) = (h(k) + i) % m (vulnerable to primary clustering).
  • Quadratic Probing: h(k, i) = (h(k) + c₁i + c₂i²) % m.
  • Double Hashing: h(k, i) = (h₁(k) + i · h₂(k)) % m.
  • Robin Hood Hashing: Steal slots from 'richer' entries to minimize maximum probe distance.
