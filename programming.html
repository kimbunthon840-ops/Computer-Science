Programming Models & Memory Architecture

How code transforms into physical silicon execution. Dive into Stack vs. Heap allocation, pointers, Garbage Collection vs Rust Borrowing, and compiler Abstract Syntax Trees.

1. Memory Topology: The Call Stack vs. The Heap

Every running operating system process is allocated a virtual address space divided into segments: Text/Code, Data/BSS, Stack, and Heap.

Deterministic LIFO

The Call Stack

Stores function call frames, local variables, parameters, and return addresses.

  • Speed: CPU register pointer shift (RSP/ESP); instant allocation and deallocation.
  • Lifetime: Automatically cleaned up when the function returns.
  • Limitations: Fixed size (typically 1MB - 8MB). Infinite recursion causes a StackOverflowError.
Dynamic Lifetimes

The Heap

Stores objects whose size is unknown at compile time or whose lifetime must outlive the caller scope.

  • Management: Explicit (C free), Garbage Collected (Go/Java), or RAII/Ownership (Rust/C++).
  • Trade-offs: Slower allocation (allocator must find contiguous free chunk), prone to memory fragmentation.
  • Risks: Memory leaks, dangling pointers, use-after-free vulnerabilities.

2. Multi-Language Syntax & Paradigm Comparison

Compare how different languages handle memory allocation, type checking, and functional paradigms. Click the tabs below to switch language implementations:

python_memory.py 
# Dynamic typing, reference counting & generational garbage collection
class BufferNode:
    def __init__(self, value: int):
        self.value = value
        self.next = None

def process_stream(items: list[int]) -> list[int]:
    # List comprehension: Functional declarative style
    return [x * 2 for x in items if x % 2 == 0]
cpp_raii.cpp 
// Static typing, deterministic destruction via RAII smart pointers
#include <memory>
#include <vector>

struct BufferNode {
    int value;
    std::unique_ptr<BufferNode> next; // Zero overhead automatic cleanup
};

std::vector<int> process_stream(const std::vector<int>& items) {
    std::vector<int> result;
    for (int x : items) {
        if (x % 2 == 0) result.push_back(x * 2);
    }
    return result;
}
rust_ownership.rs 
// Compile-time memory safety without a garbage collector
struct BufferNode {
    value: i32,
    next: Option<Box<BufferNode>>,
}

pub fn process_stream(items: &[i32]) -> Vec<i32> {
    // Zero-cost iterator abstraction
    items.iter()
        .filter(|&&x| x % 2 == 0)
        .map(|&x| x * 2)
        .collect()
}
javascript_v8.js 
// Single-threaded event loop, JIT compiled via V8 Engine
class BufferNode {
  constructor(value) {
    this.value = value;
    this.next = null;
  }
}

  items.filter(x => x % 2 === 0).map(x => x * 2);

3. The Compiler Pipeline & ASTs

How high-level human-readable code becomes executable machine instructions:

Stage 1

Lexical Analysis

Converts raw source characters into a stream of categorized Tokens (Keywords, Identifiers, Literals).

Stage 2

Parsing & AST

Checks grammar according to language syntax rules and builds an Abstract Syntax Tree (AST).

Stage 3

Semantic & IR

Type checking, scope resolution, and translation into architecture-independent Intermediate Representation (LLVM IR).

Stage 4

Optimization & Codegen

Dead code elimination, loop unrolling, register allocation, and assembly emission for target CPU (x86_64 / ARM64).
