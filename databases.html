2. ACID Guarantees in Relational Transactions

A

Atomicity

All operations succeed or the entire transaction rolls back cleanly ("All-or-Nothing").

C

Consistency

Data transitions only from one valid state to another, satisfying all database constraints and triggers.

I

Isolation

Concurrent transactions execute without stepping on each other (Read Committed, Repeatable Read, Serializable).

D

Durability

Once committed, transactions survive power cuts or hardware crashes via Write-Ahead Logs (WAL).

3. Storage Engines & B+ Tree Indexing

Why do relational storage engines (PostgreSQL, MySQL InnoDB) rely on B+ Trees rather than standard Binary Search Trees or Hash Tables?

Massive Fanout & Disk Alignment

A B+ Tree node has hundreds of keys, perfectly matching 4KB/16KB disk page sizes. A tree of height 3 can index over 10 million rows, requiring only 3 disk I/O seeks to reach any record!

Linked Leaf Range Scans

All data records or row pointers reside in leaf nodes, linked sequentially via sibling pointers. Querying ranges like WHERE date BETWEEN '2026-01-01' AND '2026-02-01' executes in lightning-fast linear pointer hops without re-traversing the root!
