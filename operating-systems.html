Operating Systems & Kernels

The software bridge between application code and hardware silicon. Explore preemptive CPU scheduling, virtual memory translation (TLB), inter-process communication, and deadlock synchronization.

1. Process Control Block & Context Switching

An Operating System process represents an active instance of a running program. The kernel manages each process via a data structure called the Process Control Block (PCB) containing PID, program counter, CPU registers, memory limits, and open file descriptors.

Process vs Thread

Memory Isolation

Processes possess distinct, isolated virtual memory spaces. Threads within the same process share the same code, data, and heap segments, but each maintain their own independent call stack and registers.

Hardware Interruption

Context Switching

When switching between processes, the CPU must save current registers to PCB, load the target process's registers, switch page directory base registers (CR3 in x86), and flush CPU cache lines.

State Machine

Process States

New ➔ Ready (waiting in queue) ➔ Running (on CPU) ➔ Waiting (I/O block) ➔ Terminated (Zombie cleanup).

2. CPU Scheduling Policies

The CPU scheduler decides which ready process is allocated the CPU core when an interrupt, I/O wait, or timer tick occurs:

Scheduler Algorithm Preemptive? Average Wait Time Characteristics & Trade-offs
First-Come, First-Served (FCFS) No High Suffers from the Convoy Effect (short jobs wait behind a massive compute-bound job).
Shortest Job First (SJF) Optional (SRTF) Optimal (Minimum) Requires predicting CPU burst length. Risk of long-job starvation.
Round Robin (RR) Yes Moderate Each job receives a slice (quantum $q$). Responsive for interactive desktop systems.
Multi-Level Feedback Queue (MLFQ) Yes Low Dynamically demotes CPU-heavy processes and prioritizes interactive I/O-bound jobs.

3. Virtual Memory, Paging & TLB

Virtual memory gives each application the illusion of a contiguous, private memory space, decoupled from physical RAM fragmentation.

Paging & Translation (MMU)

Virtual address space is split into fixed-size Pages (typically 4KB). Physical RAM is divided into matching Frames. The CPU Memory Management Unit (MMU) translates virtual page numbers to physical frames using hierarchical Page Tables.

Translation Lookaside Buffer (TLB)

Accessing RAM on every address translation is too slow. The TLB is an ultra-fast on-die hardware associative cache storing the most recent virtual-to-physical address mappings, achieving 99%+ hit rates.

4. Concurrency & Coffman Deadlock Conditions

A Deadlock is a state where a set of threads are permanently blocked because each thread holds a lock that another thread needs. A deadlock can only occur if ALL four Coffman conditions hold simultaneously:

Condition 1

Mutual Exclusion

At least one resource must be held in a non-shareable mode (only one thread can use it at a time).

Condition 2

Hold and Wait

A thread holds at least one resource and is waiting to acquire additional resources held by others.

Condition 3

No Preemption

Resources cannot be forcibly confiscated; they can only be released voluntarily by the holding thread.

Condition 4

Circular Wait

A closed chain of threads exists such that each thread waits for a resource held by the next thread in the cycle.
